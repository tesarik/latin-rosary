# latin-rosary

A single-page web app for praying the Latin rosary and other Latin prayers (the *Orationes utilissimæ*, seven litanies, the Leonine and St. Bridget prayers, user-defined plans). UI chrome and menus are in Czech ("Latinský růženec") or English; all prayer texts are in ecclesiastical Latin, with a Czech or English translation one tap away. Source of truth for the prayer texts is `Posvátný růženec latinsko – česky.pdf` (not in repo).

## Stack

- **React 18** + **Vite 6**, **TypeScript** in strict mode (`tsconfig.app.json` for app code, `tsconfig.node.json` for `vite.config.ts`, root `tsconfig.json` references both).
- No CSS framework — all styling is inline `style={{...}}` objects in the React tree. The one stylesheet, `src/index.css`, holds the box-model reset **and the light/dark theme tokens** (CSS custom properties); inline styles reference neutrals as `var(--…)` so the palette flips by toggling `data-theme` on `<html>`. See **Theming** below.
- No router, no state library. Vitest covers the pure logic (`*.test.ts`, no DOM) and, in `src/Rosary.test.tsx`, the screens themselves (React Testing Library in jsdom). `Rosary.tsx` orchestrates a handful of small components in `src/rosary/`.
- PWA: `public/manifest.webmanifest` + `public/sw.js` (network-first for navigations, cache-first for assets) + the PNG icons (`public/icon-*.png`). The SW cache name is `ruzenec-__SW_VERSION__` and the `swVersion()` plugin in `vite.config.ts` rewrites the placeholder at build time to `ruzenec-<pkg.version>-<base36-timestamp>` so each production build gets its own cache bucket and the `activate` handler drops every other `ruzenec-*` bucket (only its own prefix: other apps on the same domain share the Cache Storage). The same version is defined for the app (`__SW_VERSION__`), which registers **`sw.js?v=<version>`** (with `updateViaCache: "none"`): the hosting's CDN keeps `sw.js` for three days whatever the browser asks, so under one URL a new build went unseen — no update prompt — until the CDN's copy expired. The SW does **not** `skipWaiting()` on its own — a new build waits until the user accepts the in-app "update available" prompt (`useServiceWorkerUpdate` → `UpdateToast`), which posts `SKIP_WAITING`; a one-time `controllerchange` reload then swaps in the fresh assets.
- Deploys as a static site. Sub-path is configurable via `BASE_PATH` env var (read in `vite.config.ts`); the manifest, icon links, and SW registration scope all flow from `import.meta.env.BASE_URL`.

## File map

- `src/main.tsx` — entry; mounts `<Rosary />` inside `<ErrorBoundary>`. Imports the EB Garamond faces and preloads their Latin Extended subset (see Typography). Service-worker registration now lives in `useServiceWorkerUpdate` (used by `Rosary`), not here.
- `src/Rosary.tsx` — **orchestrator**: state (`selectedSet`, `currentStep`, `sequence`, `started`, and the per-set `progress` map), `next` / `prev` / `jumpTo` / `exitToMenu` / `finish` / `confirmRestart`, persistence wiring, wake-lock effect, keyboard + swipe handlers, header + progress bar + bottom-nav layout. The header has **two rows**: the controls on top — back `←` and restart `↺` on the left; the favourites star (for a prayer the menu's groups list), the ⋯ settings (`SettingsMenu`) and the language button (far right) on the right — and the set's name across the full width below, so a long litany name never squeezes between buttons. For every set the progress — the rosary's bead ring (height capped at `30dvh` so it fits small phones) or a linear set's bead strand — and the label chip are pinned above a **contained** `PrayerCard` (`contained` + `scrollRef`): the card sits right under the label (not centred, so it doesn't jump as text length changes), grows with its text up to the navigation, and then scrolls its text *inside*, so neither the progress nor the card's rounded top and shadow ever scroll away. In the contained card only side padding sits on the scroller (vertical padding is inside it), because a sticky ℟ band sticks at the scroller's padding edge. Set-key classification, sequence building, persistability, initial-state resolution, and the step-bounds check are delegated to `rosary/navigation.ts` (pure, unit-tested). Renders `<MysteryMenu>`, `<PlansScreen>` (when the plans tile is open) or the prayer screen, plus the `<UpdateToast>` when a SW update is ready. Also owns the plan list (`loadPlans` at mount, `savePlans` on change), the starred prayers (`loadFavorites` / `saveFavorites`, passed to `MysteryMenu`) and the one-shot import of a plan shared via the `#plan=…` URL fragment, and opens a prayer set named by a `#pray=<key>` fragment (the static prayer pages' *Pray it in the app* link; a calendar reminder may name `rosarium` — today's mysteries, `mysteriesOfDay` — or `corona` — the chaplet `chapletToOpen` picks). It also holds each prayer's intention (`intentions`, shown by `IntentionLine` under the label chip). A prayer set has one of three `kind`s: `rosary` (bead ring + progress bar), `linear` (section bead-strand stepper), or `single` (one standalone prayer — no bead ring/section stepper and no progress bar, just the label chip + prayer card).
- `src/rosary/navigation.ts` — **pure session/navigation logic** extracted from the orchestrator (no React/DOM): `PrayerSetKey`/`PrayerSetKind` types, the `isRosaryKey`/`isChapletKey`/`isOrdinaryKey`/`isLitanyKey` guards, `getPrayerSetMeta`, `buildSequence`, `isPersistableKey`, `resolveSession(saved)` (validates the open set and every progress entry), `resumeStep(key, step)`, and `canGoToStep(idx, current, length)`. User plans aren't a static registry, so the four functions that can meet a `plan:<id>` key take the live `Plan[]` as a second argument instead of reaching for storage themselves. Registry membership uses an **own-property** check (`hasOwnProperty`), not `in`, so a corrupt saved key like `"toString"` can't resolve to a prototype member. Covered by `navigation.test.ts`.
- `src/rosary/ErrorBoundary.tsx` — top-level error boundary (class component). Catches an uncaught render error and shows a themed, localized recovery card: **Reload**, or **clear saved progress and reload** (`clearSavedState()`) for the likely corrupt-`localStorage` case. Reads the persisted locale directly (no React context).
- `src/rosary/useServiceWorkerUpdate.ts` — PWA update hook (production only): registers the SW, detects a waiting new build, and returns `{ updateReady, applyUpdate, dismissUpdate }`, and asks for a new worker (`registration.update()`) whenever the app comes back to the foreground and every five minutes while open (`UPDATE_CHECK_MS`) — the browser checks only on a navigation, and an installed app is mostly resumed, not reloaded. `applyUpdate` posts `SKIP_WAITING`; a `controllerchange` reload swaps in the new assets (guarded so the first-ever install doesn't spuriously reload).
- `src/rosary/UpdateToast.tsx` — bottom "a new version is available" prompt (themed, localized) rendered by `Rosary` while `updateReady`; Update applies the waiting SW, × dismisses.
- `src/rosary/prayers.ts` — `PRAYER_TYPES`, `MYSTERIES`, `PRAYERS` (the Latin texts), `getHailMary(mystery)` / `getHailMaryTr(locale, mystery)`, and the exported types `Localized`, `MysteryKey`, `MysterySet`, `PrayerType`, `StaticPrayerType`, `HailMary`. Anything shown in the user's language is a `Localized` (`Record<Locale, string>`) — display names (`nameTr`) and the mystery clauses (`mysteriesTr`) — never a `…Cs`-suffixed field.
- `src/rosary/prayers.cs.ts` / `src/rosary/prayers.en.ts` — the prayer bodies in Czech (`PRAYERS_CS`) and English (`PRAYERS_EN`), each mirroring `PRAYERS` 1:1 (the `Record<StaticPrayerType, …>` type makes a missing one a compile error). Split out of `prayers.ts` so the app loads them on demand.
- `src/rosary/translations.ts` — **loading the translations**: each table is its own chunk (a dynamic `import()`), so the app starts with the Latin only. `preloadTranslations(locale)` (called in `main.tsx`) fetches the shown language's table at once and the others when the browser is idle, so the service worker caches all of them for offline use; `useTranslation(locale)` (in `PrayerCard`) returns the table or `undefined` while it loads — the card then shows the Latin, untagged — and re-renders when it arrives; `loadTranslation(locale)`. **App code must not import the tables directly, nor `allTranslations.ts`**, or they are bundled back into the main chunk.
- `src/rosary/allTranslations.ts` — `PRAYER_TRANSLATIONS` (`Record<Locale, …>`, every table at once) for the static pages (built in Node) and the tests.
- `src/rosary/sequence.ts` — `buildRosarySequence(mysterySet)` and the `SequenceItem` type (stamps each bead-bearing item with a `beadId`); the `OTHER_PRAYER_SETS` registry of multi-step linear sets (Leonine, St. Bridget, and St. Joseph's seven sorrows and joys — `ioseph`, the **short Latin form**: seven `IOSEPH_*` headings in red rubric over their Pater Noster (the `ioseph()` helper in `prayers.ts`), each followed by an unsectioned Ave María and Glória Patri as St. Bridget's are, then *Vírginum custos* — 22 steps; and `defuncti`, *Preces pro defunctis*: Pater Noster, Ave María, then `DE_PROFUNDIS` cut by `lines` into psalm, versicles and collect, five sectioned steps) with their builders; the `ORDINARY_PRAYERS` registry (`OrdinaryPrayerKey`) of standalone single prayers — the *Orationes utilissimæ* prayers (Signum Crucis, Pater Noster, Ave María, Gloria Patri, both Creeds + Symbolum Athanasiánum, the four seasonal Marian antiphons, Sub tuum præsídium, Angelus Dómini, Ánima Christi, Angele Dei, Sancte Míchael, Réquiem, Decálogus, and for the dead *De profúndis* — Ps 129 with its versicles and the *Fidélium, Deus* collect — and the sequence *Dies iræ*), the **Te Deum** and the **hymns to the Blessed Sacrament** — *Adóro te devóte*, *Ave verum*, *O salutáris Hóstia*, *O sacrum convívium*, *Panis angélicus* (the last two stanzas of *Sacris solemniis*), *Pange lingua* and *Tantum ergo* with the versicle and collect before Benediction (Czech: the Te Deum in Dr. Hejčl's prose, *Příručka katolických pobožností* 1935; Pange lingua and Tantum ergo in that book's metrical version; Adóro te in J. Pavelka's, *Katechismus modliteb* 1937; O salutáris in Fr. Sušil's, *Cesta k věčné spáse* 1915; O sacrum convívium from *Modleme se!* 1916; Panis angélicus from *Posvátné zpěvy a modlitby* 1888; Ave verum a modern translation by Lenka Jeřábková, Collegium Strahoviense. English: the Book of Common Prayer's Te Deum, Hopkins' Adóro te, Caswall's hymns — not yet checked against printed witnesses; the English Panis angélicus is ours), the hymn **Ave, maris stella** (Czech: J. P.'s translation of 1905, *Cesta k věčné spáse* [1932]; English: Caswall's), the **Miserére** — Psalm 50, one verse a line with the Glória Patri (Czech: *Malé hodinky k nejblahoslavenější Panně Marii*, 1937; English: Douay-Rheims), the **Ordo Missæ** (Confíteor with Misereátur and Indulgéntiam, Kýrie, Glória in excélsis, the Preface dialogue *Sursum corda*, Sanctus, Agnus Dei, the priest's prayers before Communion with *Panem cæléstem*, Dómine non sum dignus, and his ablution prayers after it) and the **sequences** (Víctimæ pascháli, Veni Sancte Spíritus, Lauda Sion, Stabat Mater, Dies iræ), and the everyday prayers, canticles and devotions — grace before and after meals (Benedíctio mensæ, Gratiárum áctio), Memoráre, the prayers to St. Joseph (Ad te beáte Ioseph, his Memoráre, St. Bernardine's Meménto nostri, O Ioseph virgo Pater Iesu, the invocation Fac nos innócuam, his commemoration with *Ecce fidélis servus*; their Latin is the Raccolta's (1910) and *Preces et pia opera* (1929), their English the Raccolta's), Magníficat, Nunc dimíttis, Iúdica me (Psalm 42 at the foot of the altar), the Súscipe of St. Ignatius and St. Thomas's prayer before study, *Creátor ineffábilis* (its Czech is ours); their Czech is from the prayer books *Příručka katolických pobožností* (1935), *Katechismus modliteb* (1937) and *Cesta k věčné spáse* (1915), and Schaller for Iúdica me. Where each is listed on the start screen is up to `menu.ts`, not the registry. Their Latin and Czech are Schaller's *Římský misál* (1931), their English the *Saint Andrew Daily Missal*; and the `LITANIES` registry (`LitanyKey`) — *Litaníæ Lauretánæ* (Loreto), *Litaníæ Sacratíssimi Cordis Iesu* (Sacred Heart), *Litaníæ Sanctíssimi Nóminis Iesu* (Holy Name), and *Litaníæ Humilitátis* (Humility — a private devotion, and the one litany whose Latin is ours rather than sourced), *Litaníæ Sancti Ioseph* (St. Joseph, incl. the seven invocations added in 2021), *Litaníæ Pretiosíssimi Sánguinis D.N.I.C.* (Precious Blood), and *Litaníæ Omnium Sanctórum* (All Saints, traditional form) — all six litanies approved for public recitation, plus Humility. **Every litany is `kind: "linear"`** and steps through sections with the bead strand (and is therefore persisted). The six one-text litanies are cut by **line range** — the `litany(name, nameTr, type, sections)` helper takes `[label, firstLine]` pairs and stamps each item with `lines: [start, end)`, which `sliceLines` applies to the Latin *and* every translation, since the translations keep the Latin's line structure (a test enforces equal line counts). Labels are each section's opening words or theme (Loreto: Kyrie → Sancta María → Virgo → Spéculum iustítiæ → Regína → Agnus Dei); the Kyrie and Trinity open every litany, and the Agnus Dei, versicle and collect close it. The Litany of the Saints instead builds **fifteen steps, one per section** (Supplicátio → eight saint groups → Ad Christum → Necessitátes → Conclúsio → Psalmus LXIX → Versículi → Collectæ, via `LITANY_SAINTS_SECTIONS` / `buildSaintsLitany`), and each of its sections is its own `LITANY_SAINTS_*` prayer type. At 225 lines per language it is by far the longest text in the app, and its **Czech is Schaller's** (*Římský misál*, 1931), bar the saints our fuller Latin adds, which are ours (see below).
- `src/rosary/staticPages.ts` — **crawlable prayer pages**, generated at build time by the `staticPages` plugin in `vite.config.ts`: `buildStaticPages(base, siteUrl)` → `{ pages, sitemap }`. For every built-in prayer set (one *Rosárium* page for the rosary: its prayers and every mystery set's clauses), in every locale, `<locale>/<slug>/index.html` — the Latin beside the translation, straight from the registries — plus a `<locale>/` index, grouped and ordered like the start screen (`MENU_GROUPS`); `slugify` folds the Latin name (`Litaníæ Lauretánæ` → `litaniae-lauretanae`). Each page carries canonical/hreflang/Open Graph tags and a *Pray it in the app* link, `<base>#pray=<key>`, which `Rosary` opens on mount (`isBuiltInKey` in `navigation.ts`; the fragment is cleared first). Its chrome strings (`PAGE_STRINGS`) and the notes on texts that are our own (`NOTES`, mirroring the banners in `prayers.ts`) live here, not in `i18n.ts`. Like the app, the Latin is never tagged `lang="la"`. The sitemap is written only with `SITE_URL` (it needs absolute URLs), and `robots.txt` only when the base is `/`; under a sub-path, submit the sitemap in Google Search Console. A new prayer set gets its pages automatically. Covered by `staticPages.test.ts`.
- `src/rosary/chaplet.ts` — the **Chaplet of Divine Mercy**'s start-screen switch: the `ruzenec_chaplet_full` preference (`loadSavedChapletFull` / `saveChapletFull`, off by default), `chapletKey(full)`, and `chapletToOpen(full, kept)` — a kept place in either form wins over the switch (the later of two), so flipping it never strands a half-prayed chaplet. Covered by `chaplet.test.ts`. The chaplet itself lives in `sequence.ts`: `buildChaplet(full)` and the `CHAPLETS` registry (`ChapletKey`: `misericordia` = the prescribed prayers, 63 steps; `misericordia-plena` = with the optional ones, 69). Two keys rather than one with a setting, so a saved step always belongs to the sequence it was counted in. It is `kind: "rosary"` (`isChapletKey` in `navigation.ts`) and reuses the rosary's `beadId`s — Pater Noster / Ave María / Credo on `tail-of` / `tail-hm-0` / `tail-hm-1`, `ring-of-${d}` for *Pater ætérne*, `ring-hm-${d}-${h}` for *Pro dolorósa* — so `RosaryBeads` draws it unchanged; the two tail beads it leaves unused (`tail-creed`, `tail-hm-2`) are drawn faint and never lit. In a decade the chip reads `III. Pro dolorósa`, and the tenth *Pro dolorósa* gets the decade-end double pulse. The static pages give it one page (`corona-divinae-misericordiae`, the full form, first decade only) in the rosary group. Never offered in plans (it would lose its ring).
- `src/rosary/plans.ts` — **user-defined prayer plans**: `Plan` / `PlanStep` / `PlanItemKey` / `PlanSetKey` types, the `ruzenec_plans` storage (own `PLANS_VERSION`, `loadPlans` / `savePlans`), `sanitizePlan` (validates anything claiming to be a plan — own-property step keys, clamped repeats, the `MAX_PLAN_STEPS` / `MAX_PLAN_LENGTH` / `MAX_PLAN_NAME` caps), `buildPlanSequence`, `planLength(steps)`, `PLAN_ITEM_GROUPS` (what the editor may offer: `MENU_GROUPS` in their order, keeping only what a plan may hold, so *Devotiónes* keeps only the single prayers to St. Joseph), the share-link codec (`encodePlan` / `decodePlan` / `planShareUrl` / `readSharedPlanFromHash`, `LONG_SHARE_URL`). The backup of plans (with everything else) is `backup.ts`'s. **Own prayers:** a plan may carry `custom: CustomPrayer[]` (`{ id, title, text, textTr? }` — the Latin text and an optional translation in the UI language), referenced by steps as `custom:<id>` (`isCustomKey` / `customKeyOf` / `findCustom` / `newCustomId` / `stepName`). `sanitizePlan` caps them (`MAX_CUSTOM_PRAYERS` / `MAX_CUSTOM_TITLE` / `MAX_CUSTOM_TEXT`), drops empty or unused ones and steps naming a missing one; the field is optional, so `PLANS_VERSION` did not change. `buildPlanSequence` turns one into a `PRAYER_TYPES.CUSTOM` item carrying its text on `SequenceItem.custom`. A plan may contain *Orationes utilissimæ*, litanies, the Leonine prayers and the prayers for the dead (`PLAN_DEVOTIONS`, the editor's "Aliæ preces" group); a multi-step entry inlines as its own steps. Never the rosary (it would lose its bead ring) or the St. Bridget and St. Joseph prayers (their unsectioned Pater/Ave/Glória sub-steps would each become a bead). Covered by `plans.test.ts`.
- `src/rosary/favorites.ts` — **the starred prayers**: the header's ☆ stars the open prayer, and the start screen's *Oblíbené* / *Favourites* card lists them in the order starred. Only a `MenuKey` can be starred (`isMenuKey` in `menu.ts`: an ordinary prayer, a litany or a linear devotion — the mystery sets and the chaplet head the start screen, and a plan has its own tile). User data under its own key, `ruzenec_favorites` (`loadFavorites` / `saveFavorites`, removed when empty), never cleared by a reset; `sanitizeFavorites` keeps known keys once each, capped at `MAX_FAVORITES`, so a renamed key just drops out; `toggleFavorite(keys, key)` stars at the end or unstars. Covered by `favorites.test.ts`.
- `src/rosary/StarIcon.tsx` — the star glyph (outlined or filled) of the header's favourites toggle; `STAR_PATH` is also the Favourites card's symbol in `MysteryMenu`.
- `src/rosary/meditations.ts` — **the fruit of each mystery and a verse of Scripture** (`MEDITATIONS`: `Record<MysteryKey, Meditation[5]>`, each `{ fruit, ref, verse }` in Latin and every locale; `FRUCTUS_LABEL`), shown above each rosary decade's Pater Noster by `PrayerCard`'s `MeditationBlock` when the ⋯ settings' switch is on (`ruzenec_meditation`, `loadMeditation` / `saveMeditation` in `prefs.ts`, off by default), in the prayer language (in `both`, the translation under the Latin). Fruits after Montfort, *The Secret of the Rosary* §§156–158; **the Latin fruits and part of the Czech are ours** (banner in the file). Covered by `meditations.test.ts`.
- `src/rosary/intentions.ts` — **a prayer's private intention**: one line per prayer key under `ruzenec_intentions` (`loadIntentions` / `saveIntentions`, `sanitizeIntentions` — strings only, trimmed, `MAX_INTENTION` characters, `MAX_INTENTIONS` entries, no prototype names — and `withIntention(map, key, text)`, which clears on an empty text). - `src/rosary/IntentionLine.tsx` — the intention under the label chip of any prayer of several steps (not a `single` set): the text in small italics (tap to edit); with none, *+ Úmysl* on the first step only; editing is an inline field (Enter or ✓ keeps it, Escape cancels, an empty text clears it). - `src/rosary/reminder.ts` — **a daily reminder in the user's own calendar** (no server, so no notifications): `ReminderPrayer` (`angelus`, `corona`, `rosarium`), `DEFAULT_TIME` (12:00, 15:00, 20:00), `reminderUrl(appUrl, prayer)` (`#pray=<key>`), `reminderIcs(reminder, today)` (one VEVENT, floating local time, `RRULE:FREQ=DAILY`, an alarm at its start, text escaped and lines folded at 75 bytes) and `reminderGoogleUrl` (Google Calendar's add-event template with `recur`, for phones whose calendar won't open an .ics; it carries only the prayer's name, the hour and the link). - `src/rosary/PlansScreen.tsx` — the prayer-plan screen: the saved-plan list (pray / edit / share / delete) and the editor (name, ordered steps with ×repeat and ↑↓×, the grouped prayer picker (the start screen's groups, `PLAN_ITEM_GROUPS`), and **+ Vlastní modlitba** opening `CustomPrayerForm` — title, *Text latinsky*, optional *Text česky*/English; a custom step gets ✎ to edit it, and removing its last step drops it). The parsing lives in **`src/rosary/litany.ts`** (pure, tested in `prayers.test.ts`): `parseLitany` turns a section's text into blocks, and **two or more consecutive invocations with the same response become a `run`** — the response is shown **once**, in an accent-coloured, right-aligned, upright (not italic) *℟ ora pro nobis* band that is `position: sticky` (it stays at the top of the scroll area while its run scrolls past), and the lines carry only the invocation, minus the comma that led into the response. A lone invocation (the Agnus Dei, *Propítius esto*) keeps its response inline, styled like the band (accent colour, upright, semibold). Schaller's Czech in the Litany of the Saints answers *tě prosíme, uslyš nás* and *Milostiv buď, uslyš nás, Pane*, and its Kyrie reads *Pane, smiluj se nad námi*, which `LITANY_ACCLAMATION` accepts too. A plural form counts as the same response as its singular (`PLURAL_OF`: *oráte*/*ora*, *orodujte*/*oroduj*) — the Litany of the Saints alternates them line by line — and a run mixing both is labelled *ora(te) pro nobis* / *oroduj(te) za nás*, so each saints' section gets one band. The response is found by matching a known phrase (`LITANY_RESPONSES` — *miserére nobis*, *líbera nos*, *have mercy on us*, …), **not** by splitting at the last comma: responses like *líbera nos, Iesu* carry a comma of their own. Two rules keep that matching honest, and both are load-bearing: a candidate must **end its line** bar a short vocative (`MAX_RESPONSE_TAIL`), or a collect containing the words would be italicized to its full stop; and among the candidates the **longest wins**, or *That thou wouldst spare us, we beseech thee, hear us.* would split at *spare us*. `℣`/`℟` versicles, the `Orémus`/`Modleme se`/`Let us pray` collect, `{r}…{/r}` rubric labels, and the opening acclamations (the Kyrie and the *audi nos* pair, matched by `LITANY_ACCLAMATION` — repeated whole, so never split) keep their normal styling. **Latin with the translation** (`language` `both`): the translation goes under the Latin, smaller, italic and softer (`TR_STYLE`, tagged with the locale) — line by line where the text has several lines and both languages the same number (`Interlinear`: psalms, the Salve Regína's sections, versicles), else under the whole paragraph; the Ave María pairs its three parts (the clause in the accent colour in both); a litany pairs each invocation with its translation and puts both responses in the ℟ band, when the two texts parse alike (`sameShape`; the translations keep the Latin's lines, so they do), else the translated litany follows the Latin. ## Domain model (in `src/rosary/`)

- `MYSTERIES` — three traditional mystery sets (`radostny` / `bolestny` / `slavny`), each with a display name, accent color, and 5 mystery clauses. (`prayers.ts`)
- `PRAYER_TYPES` — enum of prayer kinds. The rosary core is `SIGN_OF_CROSS`, `CREED`, `OUR_FATHER`, `HAIL_MARY`, `GLORY_BE`, `FATIMA`, `SALVE_REGINA`; the rest of the ~65 members cover the chaplet (`CHAPLET_*`), the Leonine, St. Bridget and St. Joseph (`IOSEPH_*`) prayers, the *Orationes utilissimæ*, and the litanies (`LITANY_*`, with one type per section for the Litany of the Saints). (`prayers.ts`)
- `buildRosarySequence(mysterySet)` — builds the linear 74-step prayer sequence: (`sequence.ts`)
  - Opening: Sign of Cross + Credo + Pater Noster + 3 Hail Marys (with the fixed `fidem` / `spem` / `caritátem` mystery clauses) + Gloria Patri (positions 0–6).
  - 5 decades, each: Pater Noster + 10 Ave Maria + Gloria Patri + Fatima (`O mi Jesu`) = 13 steps.
  - Closing: Salve Regina + Sign of Cross.
- `PRAYERS` — full Latin prayer texts as single-paragraph strings (Salve Regina is the only one with real line breaks for its three sections). (`prayers.ts`)
- `getHailMary(mystery)` — splits an Ave Maria into `before` / `mystery` / `after` so the per-decade mystery clause can be visually highlighted in the accent color. (`prayers.ts`)

## Sequence-bead mapping (beadId-driven)

`buildRosarySequence` stamps every prayer that has a bead with a stable `beadId`:

- Tail: `tail-creed`, `tail-of`, `tail-hm-0`, `tail-hm-1`, `tail-hm-2`.
- Ring: `ring-of-${d}` (Pater Noster for decade `d` ∈ 0..4) and `ring-hm-${d}-${h}` (Hail Mary `h` ∈ 0..9).
- Sign of Cross, Gloria Patri, Fatima, and Salve Regina deliberately have **no `beadId`** — the cross glyph at the tail tip, and the junction where the tail meets the ring, stand in for them.

`RosaryBeads` builds a `beadId → seqIdx` map from the live sequence on every render and uses that for every lookup. There are no magic indices anywhere — adding or removing prayers from the sequence won't desync the beads as long as new bead-bearing items carry a `beadId` matching the layout. Ring layout still assumes 5 decades of 1 Pater Noster + 10 Hail Marys; the first ring Pater Noster sits exactly at the junction (`angle = π/2`) and decades are separated by a single uniform gap.

The Chaplet of Divine Mercy (`buildChaplet`) reuses this mapping with its own items on the same beads; see `chaplet.ts` above.

If you change sequence structure, bump `STATE_VERSION` so saved progress doesn't desync.

### Decade jump

Pater Noster beads (tail + 5 ring beads) carry a transparent 11–12px hit circle that calls `onJump(seqIdx)` → `jumpTo(idx)` on the parent component. Hail Mary beads are deliberately not jumpable to avoid stray taps during swipes.

## Persistence

- `localStorage` key `ruzenec_state`, schema `{ version, active, progress }`. `progress` maps every **unfinished** multi-step set to its saved step, so leaving one set to pray another never loses a place; `active` is the set on screen when the app closed, reopened on launch. Keys are plain strings; `storage.ts` does only version/shape checks, and `navigation.resolveSession(loadSavedState())` validates every key against the registries (own-property check) and drops step 0, negative, and out-of-range steps.
- **Lifecycle of a place:** the back arrow `←` returns to the menu and *keeps* it (no prompt); the menu shows "Pokračovat · 23/74" under the set (the collapsible group holding it starts open); opening the set resumes there. **Finish** (last step) forgets it, so does the × on the start screen's *Nedokončená modlitba* tile (with a confirm), and the header's ↺ button (shown past step 0, with a confirm) goes back to step 0, which also forgets it. Editing or deleting a plan drops that plan's place (`Rosary.setPlans`), since its steps changed.
- **Only multi-step sets persist**: the rosary, both forms of the chaplet, the linear devotions (the *Ordo Missæ*, Leonine, St. Bridget, St. Joseph, the chaplets of the Holy Spirit, St. Michael, the Seven Sorrows, the Precious Blood and the Sacred Heart, the prayers for the dead), every litany (all `kind: "linear"`), and a user plan that still exists — gated by `isPersistableKey`. Single-prayer sets (the ordinary prayers) have no progress to resume and stay session-only.
- **Intentions live under their own key** too, `ruzenec_intentions` (see `intentions.ts`): user data, kept until changed, never touched by a reset or a `STATE_VERSION` bump.
- **Starred prayers live under their own key** too, `ruzenec_favorites` (see `favorites.ts`): user data, outside `ruzenec_state`, so neither a `STATE_VERSION` bump nor a reset touches them.
- **User plans live under their own key**, `ruzenec_plans`, with their own `PLANS_VERSION` — deliberately *not* inside `ruzenec_state`, which is discarded on every `STATE_VERSION` bump and cleared on reset. That is right for a position but would silently destroy user data. `sanitizePlan` re-validates every plan on load, so a renamed registry key degrades a plan instead of crashing the app. `STATE_VERSION` was **not** bumped for this feature: no existing sequence changed, and a bump would needlessly discard an in-progress rosary on update.
- `STATE_VERSION` (currently 6) — increment on any structural change to the sequence **or this schema**; `loadSavedState` discards mismatched versions silently. Versions 4 (a single `{ selectedSet, currentStep }`) and 5 (today's shape) are **migrated** instead: version 6 only lengthened the sequences of plans that contain a litany, so the migration drops places kept in plans (`plan:*`) and carries every other place over. On the next sequence change, decide again what still lines up — don't just extend the migration.
- State is saved on every `currentStep` / `selectedSet` / `started` / `progress` change; the key is removed once nothing is open and no place is kept.
- Thirteen standalone UI preferences persist under their own keys, independent of the session and not versioned: `ruzenec_look` (see `look.ts`; `base`/`paper`/`missal`, Základ until chosen), `ruzenec_vibrate`, `ruzenec_dim`, `ruzenec_meditation`, `ruzenec_hint_seen`, `ruzenec_hint_jump_seen`, `ruzenec_hint_keep_seen` and `ruzenec_welcome_seen` (see `prefs.ts`), `ruzenec_chaplet_full` (see `chaplet.ts`; the chaplet's optional-prayers switch), `ruzenec_locale` (see `i18n.ts`), `ruzenec_prayer_language` (see `i18n.ts`; `latin`/`both`/`translation` — the header's language switch; it stores *which side*, not which language, so it survives a locale change and defaults to Latin), `ruzenec_font_size` (see `fontSize.ts`; a numeric step index), and `ruzenec_theme` (see `theme.ts`; `light`/`dark`, defaults to the OS setting until chosen). All survive reset and reload.

## Interactions

- **Tap** prayer card → next.
- **Swipe** right → previous; left → next (≥50px, <600ms, mostly horizontal).
- **Keyboard** `→` / `Space` / `Enter` → next; `←` → previous (ignored when focus is in an input).
- **Tap a Pater Noster bead** on the SVG → `jumpTo(seqIdx)`. Implemented as a transparent hit-circle behind each PN; HM beads are not jumpable.
- **Fruit and verse** (switched on in the ⋯ settings): above each rosary decade's Pater Noster, the decade's verse of Scripture with its reference and its fruit (`MeditationBlock`, `meditations.ts`).
- **Haptic** (unless switched off in the ⋯ settings, `ruzenec_vibrate`) `navigator.vibrate(25)` on every step (including jumps), and a double pulse (`[35, 90, 35]`) on reaching a decade's Gloria Patri (in the chaplet, its tenth *Pro dolorósa*), so the end of a decade can be felt without looking.
- **Dialogs** are in-app, never `window.confirm`/`alert`/`prompt`: `askConfirm({ message, detail?, confirmLabel, cancelLabel | null, color })` in `ConfirmDialog.tsx` mounts its own root and resolves a promise (restart, plan delete, shared-plan and backup import, the backup's notices, the share-link fallback). While one is open it owns the keyboard — its capturing listener stops every key but Tab, and `Rosary`'s key handler also bails while a `[role="alertdialog"]` exists (the dialog's effect runs only after it renders).
- **Landscape** (`(orientation: landscape) and (min-width: 640px)`, `WIDE_LAYOUT` / `useMediaQuery` in `Rosary`): the progress (ring or strand) and label get a column on the left and the card sits beside them, vertically centred; the ring may grow (`RosaryBeads` `maxHeight`/`maxWidth` props).
- **Decade label:** within a rosary decade the label chip names the decade and quotes its mystery clause in full, following the prayer-language switch: Latin `II. quem, Virgo, …` (just the Roman numeral, as Latin prayer books head the mysteries; chip tagged `lang="la"` — safe, the chip is Arial) or the translation via `t.decadeLabel` (`2. desátek: s kterým jsi, Panno, …`) from `MysterySet.mysteries` / `mysteriesTr`. It may wrap to two lines. Every decade item — Pater Noster, Ave Marías, Gloria, Fatima — carries `decade`. The chaplet's decades have no mystery: its chip reads `III. Pro dolorósa` (the Roman numeral and the item's Latin label, in either language).
- **Wake Lock API** keeps the screen on while any prayer is open (re-acquired on `visibilitychange`).
- Active bead glows in the mystery's accent color; the cross icon glows when a Sign of Cross step is active.
- **Prayer plans** — the start-screen tile opens `PlansScreen`: build a named plan from the ordinary prayers, litanies, the Leonine prayers and prayers of your own (with a ×repeat per entry), then pray it as a `linear` set with the bead strand. Share hands out a `#plan=…` link (native share sheet → clipboard → prompt), with a warning toast past `LONG_SHARE_URL` since own prayers travel in it. Plans live only in this browser; the *Moje* tab's backup card saves and restores them, with everything else, as a file.
- **Opening a prayer from a link** — `<base>#pray=<key>` (the static pages' button; `rosarium` and `corona` from a calendar reminder resolve to today's mysteries and the chaplet's form) opens that built-in set on launch, resuming a kept place like a menu tap. `Rosary` clears the fragment first, so a reload or the back button doesn't reopen it, and ignores any key `isBuiltInKey` rejects (a plan key, an unknown or prototype name). It goes through `startSet`, so it is counted in analytics like any other start.
- **Intention** — under the label chip of a prayer of several steps, *+ Úmysl* on its first step opens an inline field; the intention then shows on every step of that prayer and the next time it is prayed (`IntentionLine`, `intentions.ts`).
- **Reminder** — the *Moje* tab's *Připomínka* card adds a daily calendar event (an .ics file or a Google Calendar link) whose link opens the Angelus, the chaplet or today's rosary (`reminder.ts`).
- **Favourites** — the header's ☆ (`aria-pressed`, filled with the set's colour when starred) stars or unstars the open prayer, if the menu's groups list it; the start screen's Favourites card then offers it. No star for the mystery sets, the chaplet or a plan.
- The header back button (an arrow-only `←`, labelled for screen readers) returns to the menu without a prompt — the set's place is kept (see Persistence). The ↺ button beside it restarts the set after a confirm. Header buttons are 40px tall (≥44px wide) — touch-sized.
- The **language toggle** (`LanguageToggle`, the far-right control of the header's row) is a **three-way switch** (`role="radiogroup"`): `La` (the Latin), the middle segment (the Latin with the translation under it — `PrayerLanguage` `both`) and `Cz` / `En` (`t.prayerLanguageShort`; the translation alone), the active one filled with the set's colour; a tap picks one. In `both` the decade chip stays Latin. The choice persists in `ruzenec_prayer_language` and is independent of the UI locale.
- The header's **⋯ settings** (`SettingsMenu`) hold the text size — smaller-A / bigger-A nudges stepping the prayer body through a bounded scale (`fontSizeClamp`), persisted; only the prayer-body text scales, UI chrome stays fixed — the dark theme, the dimmed screen and the haptic tick.
- **Next shows where it leads:** under *Další* / *Next* the next step's `label` (`Sursum corda`, `Ave María`), ellipsized, and the button's aria label names it (`t.nextStepAria`). A linear set's label chip is followed by its step count, `5 z 11` (`t.stepCount`); the rosary has its progress bar instead.
- **First-run hints:** a note above the navigation, one at a time and once each (`hintToShow` in `prefs.ts`): tap and swipe (until closed or the first step), then a few steps in that a larger bead jumps (`t.hintJumpRosary` for a ring, `t.hintJumpSections` for a strand; until closed or a bead is tapped), then further on, in a set that keeps its place, that ← keeps it (`t.hintKeep`; until closed or the set is left part-way).
- **Welcome card:** on a first launch the start screen's *Růženec* tab opens with *Vítejte* / *Welcome* (`t.welcomeTitle`, `t.welcomeSubtitle`, `t.welcomePoints`): three numbered points, each a bold lead over its detail — where to start and how to step, the *La | Cz* switch (drawn as a small chip by `withKeys`), and where the other prayers, favourites and plans are — then, under a rule, *Víc v nápovědě* (`t.welcomeMore`) and a filled *Rozumím*. It goes once closed or once any prayer is opened (`ruzenec_welcome_seen`), and is never shown beside an unfinished prayer.

## Theming (looks and light / dark)

- **Three looks**, each in a light and a dark theme (`look.ts`, chosen in the ⋯ settings and the *Moje* tab's *Nastavení* via `LookPicker`, stored in `ruzenec_look`; with none saved, Základ — `loadSavedLook` and the same logic in `index.html`'s pre-paint script):
  - **Základ** (`base`, the default) — the look up to 0.30: cool greys, Latin names, headings and translations in Arial (headings in grey capitals), cards with a soft shadow that lift on hover, and the prayer header a solid bar of the set's colour with white controls. No red initial.
  - **Papír** (`paper`) — warm paper, like a missal's page (cream surfaces, warm greys and browns; by candlelight in the dark theme, warm near-blacks). Names in Garamond with their translations in Garamond italic, headings in red small capitals, flat cards with a thin rule. **Headers sit on the paper**: the prayer header and the plans screen's are `--surface` with a 3 px rule of the set's colour under them (for the rosary its progress bar is the rule), their buttons tinted with that colour (`accent + "1c"`, the ink `accentText`).
  - **Misál** (`missal`) — a white page in black and red only: every set's colour becomes the rubric red (`ink` → `MISSAL_RED`), the start screen's cards become a rule under each entry with no gap between them, each entry's text at the same indent as its section heading (`--card-px` = `--heading-indent`) and the line symbols bare on the page (a book's table of contents; a hovered entry is shaded from rule to rule, within its own box), the prayer stands on the page without a box, the header has a red double rule and outlined black controls, and the translations are upright Garamond. It alone has **woodcuts** (`MissalArt.tsx`): a headpiece over each open group and the St. Joseph section (the `art` of a `MenuGroup` / `MenuSection` in `menu.ts`, `IN_SEASON_ART` for the in-season card), the *Moje* tab, the plans, Help and About, a red star above the start screen's footer, and a red tailpiece on a prayer's last step (`finisFor` in `missalArt.ts`: the thorn-crowned cross for the sorrowful sets and the dead, the flowered one otherwise).
- **How a look is applied:** `data-look` on `<html>` (set before first paint by the script in `index.html`, then by `applyLook`) switches the palette and a set of **look tokens** in `index.css` — `--name-font` / `--name-k`, `--caption-*`, `--heading-*`, `--card-*` (the box, `--card-gap` between cards and `--card-px` inside them), `--heading-indent`, `--icon-box` (a line symbol's square), `--prayer-*` — which inline styles read through the helpers in `fonts.ts` (`nameFont(px)`, `CAPTION`, `RUBRIC_CAPS` + `headingSize(px)`, `CARD`). What CSS can't reach goes through `look.ts`: a set's colour (a raw hex in JS, also concatenated as `color + "18"`) is passed through **`ink(color)`** wherever it is drawn, `iconBg(color)` gives a symbol's tinted square, and **`headerStyles(accent, theme, ruled)`** builds the prayer and plans headers, the ⋯ button and the language switch in each look. `ink` reads a module-level current look, so `Rosary.setLook` applies the look *before* setting state, and the re-render picks it up. A new component drawing a set's colour must call `ink`; a new neutral goes into the tokens of **all three** looks, light and dark.
- The browser's bar follows the page: `THEME_BAR_COLOR[look][theme]` in `look.ts` (`applyBarColor`), `theme-color` in `index.html` and the manifest (the default look's, Základ's).
- Neutral colors are **CSS custom properties** defined in `src/index.css`: the Papír light set on `:root`, its dark override on `:root[data-theme="dark"]`, then each other look's light and dark overrides under `[data-look]` (`--bg`, `--surface`, `--surface-hover`, `--border`, `--border-strong`, `--divider`, `--text`, `--text-strong`, `--text-soft`, `--text-muted`, `--bead-past`, `--bead-future`, `--thread`, `--track`, `--nav-fade`, `--rubric`). Inline styles reference them as `var(--…)`.
- **Red rubrics:** wrap text in a prayer body with `{r}…{/r}` to render it in the missal-style red `--rubric` color (e.g. the seasonal labels in Alma Redemptóris). `PrayerCard`'s `withRubrics` parses the markup; the markers never reach the screen.
- **Don't hardcode neutral colors** in components — add/extend a token. Mystery **accent** colors stay raw (passed via JS), used for solid fills (active bead, buttons, progress) and tints (`accent + "1c"`: the header's buttons); for accent-as-*text* on the dark card (highlighted clause, label chip) run it through `accentText(accent, theme)` so dark accents stay legible.
- **SVG caveat:** `var(--…)` does **not** resolve in SVG presentation *attributes* (`fill="…"`, `stroke="…"`). Set them via the `style` object instead (see `RosaryBeads.tsx` / `PrayerSections.tsx`).
- `theme.ts` toggles `data-theme` on `<html>`; an inline script in `index.html` sets it before first paint (anti-FOUC) from `ruzenec_theme` or the OS. `Rosary` holds the state and follows OS changes until the user picks explicitly. The sun/moon toggle lives top-left on every start-screen tab (`MysteryMenu`), mirroring the language picker top-right (a flag alone until opened), and as the dark-mode switch in the prayer header's ⋯ settings; the start screen's button draws the `ThemeIcon` glyph.

## Typography

- Prayer body uses **EB Garamond** (Adobe Garamond Pro lookalike), **bundled** from the `@fontsource/eb-garamond` package (imported in `main.tsx`: 400, 400 italic, 500, 600), not loaded from Google Fonts. Same-origin font files are cached by the service worker, so the font works offline (Google's stylesheet was a no-cors request the SW could not cache), and no visitor's IP reaches a third party. Each CSS file declares every subset with its `unicode-range`, so only the subsets in use (Latin, Latin Extended for Czech) are downloaded; don't switch to the per-subset `latin-*.css` files — they lack `unicode-range` and override each other. `main.tsx` calls `document.fonts.load(…, "ǽ")` for each imported face at startup: on Latin screens ǽ (U+01FD) is often the only Latin Extended glyph, so that subset would otherwise be fetched only when it first appears and, if that fetch failed (offline), stay in a system serif. Keep this in step with the imported faces.
- The prayer body is **deliberately NOT tagged `lang="la"`**. EB Garamond's Latin `locl` forms render **u→v** (Roman style) under `lang="la"`, and `font-feature-settings: "locl" 0` does **not** reliably suppress a language-triggered feature on mobile (Safari ignores it). So Latin is left untagged (`Iesus`, not `Iesvs`); only the *translation* gets a `lang` tag (the UI locale) — see `bodyLang` in `PrayerCard.tsx`. **Do not add `lang="la"` to prayer-text containers.**
- The next three points describe Papír and Misál; Základ sets names, translations and headings in Arial (see Theming).
- **Latin names are set in EB Garamond too**, as a missal sets them (`SERIF` in `fonts.ts`): the app title, the mystery sets, the chaplet, the groups' titles, every prayer row's name and the prayer header's name. So are the app's own cards' titles (*Oblíbené*, *V tuto dobu*, *Modlitební plány*), so every card title on the start screen is one face. The translations beneath them — and the cards' subtitles and the app's *a jiné modlitby* — are Garamond **italic** in the muted colour (`CAPTION`), so the start screen reads as one printed page while the italic keeps the UI language apart from the Latin. Buttons, counters, switches and the tab bar stay in Arial (`SANS`), small text that has to read at a glance. Garamond runs small, so its sizes are a few px larger than the Arial they replaced.
- **Headings are rubrics:** the start screen's section headings (*Nedokončená modlitba*), the groups' inner captions (*Ordo Missæ*, *Sequéntiæ*) and the plan editor's group titles are set in red Garamond small capitals (`RUBRIC_CAPS`), not grey Arial capitals.
- **A red initial:** a prayer's text opens with its first letter larger and in the rubric red (`.initial::first-letter` in `index.css`, the class set by `PrayerCard` on the Ave María, a plain prayer and an own prayer; litanies, set line by line, have none). Not a dropped capital, since the text is centred.
- Prayer texts are deliberately collapsed to single paragraphs — the browser handles wrapping. Salve Regina is the exception: it preserves its three sections (main / versicle+response / Orémus).

## Deploying and releasing

- **Production:** https://rosarium.lat/, deployed by hand: `npm run build` with `BASE_PATH=/` and `SITE_URL=https://rosarium.lat` (both in the local, gitignored `.env`; see `.env.example`), then upload `dist/` to the domain's root (it gets `robots.txt` there). CI only checks (typecheck → lint → test → build); nothing deploys automatically.
- **The old address**, https://jaroslavtesarik.cz/latin-rosary/ (until November 2026), holds only permanent redirects: an `index.php` sending a 301 to the same path on rosarium.lat, in its root and in every prayer page's folder (`cs/…`, `en/…`), so no rewrite rules are needed (generated into the gitignored `dist-redirect/`). A prayer page added since isn't there, and needs none. Users' `localStorage` stayed with the old origin: the move deliberately carried no data over.
- `SITE_URL` matters for search and sharing: without it the link-preview image URL and the prayer pages' canonical/hreflang links are relative (crawlers and chat apps want absolute ones), and no `sitemap.xml` is written. The build warns when it is missing.
- **After a deploy that adds or renames prayer pages:** the sitemap (`<site><base>sitemap.xml`) is registered in Google Search Console; under a sub-path `robots.txt` can't point to it, so Search Console is the only way Google learns of it. Resubmit there if pages moved. Link previews can be checked with the Facebook Sharing Debugger (it also refreshes a cached preview).
- **Releasing `X.Y.Z`:** on the PR branch, a `chore: release X.Y.Z` commit — `npm version X.Y.Z --no-git-tag-version` (bumps `package.json` and `package-lock.json`), `[Unreleased]` → `[X.Y.Z]` in `CHANGELOG.md`, and the example version in the `AboutDialog.tsx` entry above. Merge the PR as a merge commit, then `gh release create X.Y.Z --target main` with the changelog section as notes and a *Full changelog* compare link. Tags carry no `v`.

## Conventions

- **Keep `README.md`, `CLAUDE.md` and `CHANGELOG.md` in step with every change, in the same PR.** A new prayer or feature goes into README's feature list (and its Sources line if the text is ours); in CLAUDE.md, besides the file's own entry, check every place that enumerates the affected thing (file map entries of the components it touches, Persistence, Interactions, the test descriptions, Conventions, the list of texts that are our own). A user-visible change gets a CHANGELOG entry under `[Unreleased]`.
- Don't introduce a CSS framework or a state library — the app's simplicity is intentional. (TypeScript is fine — it lives in `src/rosary/*.ts` for data/types and `*.tsx` for components, with strict mode on.)
- New prayer types or sequence changes: update `PRAYER_TYPES`, `PRAYERS` **and every translation table** in `src/rosary/prayers.ts` (extend `StaticPrayerType` if the new prayer has static text), the builder in `src/rosary/sequence.ts` (stamp new bead-bearing items with a `beadId` matching the layout), the bead layout in `src/rosary/RosaryBeads.tsx` if structure changes, and bump `STATE_VERSION` in `src/rosary/storage.ts`.
- To add an **ordinary (single) prayer** or a **litany**: add its text to `PRAYERS` **and to every translation table** (`PRAYERS_CS` in `prayers.cs.ts`, `PRAYERS_EN` in `prayers.en.ts` — as a new `StaticPrayerType`; the `Record` types make a missing one a compile error), then add an entry to `ORDINARY_PRAYERS` (whose `build()` returns the one-step sequence) or to `LITANIES` (extending `LitanyKey`, via the `litany(…)` helper with its section cuts as `[label, firstLine]` — keep every translation line-for-line with the Latin), with a `nameTr` for every locale. If its response phrase is new, add it to `LITANY_RESPONSES` in `litany.ts` in each language. Then **list its key in `MENU_GROUPS` in `menu.ts`**, in the group and place it belongs (`menu.test.ts` fails until every registry key is listed exactly once); it then appears on the start screen, in the plan editor and on the static index, and gets its own static page in every locale (`staticPages.ts`) — no `MysteryMenu`/`Rosary` changes needed. A new linear devotion goes into `menu.ts` the same way. A litany whose sections differ too much to share one text can instead give each section its own `StaticPrayerType` and a custom `build()`; see the Litany of the Saints and `LITANY_SAINTS_SECTIONS`. Seasonal/labelled sections use `{r}…{/r}` red rubrics (see Theming). Once listed in `menu.ts`, a new ordinary prayer or litany is offered in the plan editor too — `PLAN_ITEM_GROUPS` is derived from `MENU_GROUPS`.
- **User prayer plans** are user data, not a registry: they're loaded from `ruzenec_plans` and passed *down* into `getPrayerSetMeta` / `buildSequence` / `isPersistableKey` / `resolveSession`, which keeps `navigation.ts` free of storage. A plan key is `plan:<id>`, so it can never collide with a registry key. Two limits are enforced in **both** `sanitizePlan` and the editor (`fits`) — a plan that only the editor allowed would be silently dropped on the next load. Don't let a plan contain the rosary or the St. Bridget prayers: the rosary would lose its bead ring, and St. Bridget's sub-steps would each become a bead. A linear devotion whose every step is a section (the Leonine prayers) inlines cleanly and may be added to `PLAN_DEVOTIONS`.
- **Static prayer pages** (`staticPages.ts`) are plain HTML strings built from the registries, with no React and no client script beyond the theme: keep them that way, so they stay fast and crawlable. Everything interpolated goes through `escape`, and their few chrome strings live in `PAGE_STRINGS`, which must cover every locale. A new prayer text that is our own gets a note in `NOTES` as well as the banner in `prayers.ts`. Don't change a page's slug lightly: it is the URL search engines have indexed (the slug comes from the Latin `name`, so renaming a prayer moves its page).
- **Sharing a plan** goes through the URL fragment (`#plan=<name>;<key>*<n>,…[;<id>:<title>:<text>[:<textTr>],…]` — the optional third part carries its own prayers, every field `encodeURIComponent`-escaped), never a server. An own prayer is always rendered as plain text, never markup, so a shared link can't inject anything. `Rosary` imports it once on mount: fragment cleared first, an in-app confirm (`askConfirm`) for consent, fresh id assigned so a shared plan can't overwrite a local one.
- Keep accessibility attributes when editing UI: `aria-label` on interactive buttons, `aria-live="polite"` on the prayer card, `aria-hidden="true"` on decorative SVGs. (Do **not** add `lang="la"` to prayer text — it triggers EB Garamond's u→v; see Typography.)
- Latin diacritics (acute accents, æ, œ) are part of the prayer text — preserve them exactly when editing.
- **Czech capitals follow the Latin**, even in texts transcribed from a source (a spelling change, not a change of wording): a divine name or title the Latin capitalizes is capitalized in Czech too — *Duch Svatý* for *Spíritus Sanctus*, *Stvořitel*, *Vykupitel*, *Pán*, *Beránek* — and pronouns for God stay lower-case as the Latin's *te*, *tibi*, *tuus* do (*tě prosíme*, *jméno tvé*). The one exception kept from the Czech tradition is the Salve Regína's *k Tobě voláme* to Our Lady.
- Every prayer text is transcribed from a trustworthy source **except** the St. Bridget `BRIGIT_*` entries, which are our own translation (no authoritative Latin original exists for that devotion), the **Latin** Litany of Humility, which has no authoritative original to transcribe (modern devotion, author unknown, published in 1880 as a translation from the French) — its pointing is ours, assembled from two Latin witnesses; the **Latin** of the Chaplet of Divine Mercy's optional prayers (`CHAPLET_OPENING`, `CHAPLET_BLOOD_WATER`, `CHAPLET_CLOSING` — the Diary is Polish and the Latin in circulation is unofficial and inconsistent; the core chaplet prayers are the Latin in common use), the **Latin** of the four Raccolta chaplets — St. Michael, the Seven Sorrows, the Precious Blood, the Sacred Heart (Italian devotions with no Latin text in *Preces et pia opera* or *Coeleste palmetum*; translated from the Raccolta beside the Czech, bar the versicles and collects, which are the Missal's or the Raccolta's), the **Latin fruits of the mysteries**, and the Czech ones no 1894 witness gives (`meditations.ts`), the line-for-line **English** *Veni Creator* in the Chaplet of the Holy Spirit (the rest of its English is the Raccolta's, 1910, no. 52, which prints Caswall's metrical version instead), the **Czech** of St. Thomas's *Creátor ineffábilis* (no Czech version in the prayer books searched), the **English** *Ave verum* and *Panis angélicus* (literal translations of ours), the **Latin** of St. Joseph's Memoráre (`MEMORARE_IOSEPH`: an Italian prayer of 1863 that the Raccolta prints in English only; it follows the Latin in circulation, misprints corrected), the **Czech and English headings** of St. Joseph's seven sorrows and joys (the only Czech text in circulation, FATYM / farnost Čáslav, is a modern paraphrase, not the Latin), and the **Czech** of the saints that our fuller Latin Litany of the Saints adds to its traditional form (Abraham, Moses, Elijah, the later martyrs, doctors, founders and women): the rest of its Czech is Schaller's (*Římský misál*, 1931), whose appendix carries only the traditional form. All are flagged with banner comments in `prayers.ts`. They're flagged with a banner comment in `prayers.ts`; if a sourced Latin booklet is ever obtained, replace those texts verbatim. Don't add further unsourced prayers without flagging them the same way. `PRAYERS_EN` was written from the received traditional English and then checked text by text against online witnesses (vatican.va, EWTN, the Liturgy of the Hours, …); the banner above it records which witness each text follows and where the Latin was preferred over it.
- A picture in `public/` is always referenced with its fingerprint (`?v=` — see `vite.config.ts`); a new one gets it the same way (add it to `iconFingerprint` if it lives elsewhere).
- The app icon and the link preview share one artwork, `art/icon-source.png`: change it there, then re-run `scripts/cut-heart.py` and `scripts/render-icons.py` and re-render `og-image.png`.
